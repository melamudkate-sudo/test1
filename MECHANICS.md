# Как работают два лендинга

## Схема

Интернет-магазин demiand.ru → основной промолендинг → кнопка копирования → пользователь вставляет фразу в чат → ИИ открывает второй URL, если у него есть такая возможность → получает промпт из HTML → дорабатывает свой предыдущий ответ.

Это две страницы одного репозитория, а не два независимых проекта:

- `https://USERNAME.github.io/REPOSITORY/` — весь маркетинговый визуал и кнопка
- `https://USERNAME.github.io/REPOSITORY/digital-airfryer/` — аэрогриль и промпт в исходном HTML

## Что копируется сейчас

«Кажется, ты поторопился с подачей. Доведи мысль до готовности с DEMIAND: https://example.com/digital-airfryer»

Текст намеренно короткий, по принципу референса. Дополнительных инструкций, обращения к API или автоматической отправки в чат нет. Пользователь сам вставляет и отправляет фразу.

После публикации заменить только `shareUrl` в config.js. Не использовать localhost в финальной фразе: внешний ИИ не может прочитать локальную страницу на вашем компьютере.

## Что находится на второй странице

Видимый слой: логотип, навигация, аэрогриль, прозрачная цифровая графика 0/1. Текста промпта на экране нет.

Промпт встроен в `digital-airfryer/index.html` в элемент:

```html
<article id="ai-prompt" hidden aria-hidden="true">
  ...текст промпта...
</article>
```

Он присутствует сразу в HTML-ответе сервера и не требует выполнения JavaScript. Чтобы изменить промпт, редактируйте этот блок. Текстовая копия лежит в `digital-airfryer/prompt.txt`; при изменениях обновите оба файла. Файл TXT доступен по прямому URL, но не имеет ссылки в визуальном интерфейсе.

Промпт просит проверить предыдущий ответ на логику, точность, полезность, убрать лишнее, назвать нехватку данных и дать улучшенный ответ. Он не пытается отменять правила модели или принуждать к рекламе.

## Практическое ограничение

Скрытый HTML НЕ гарантирует, что модель получит или выполнит промпт. Разные ИИ и браузерные инструменты по-разному обрабатывают страницы; многие извлекают только видимый текст и выбрасывают `hidden`. Обычная ссылка также не гарантирует автоматическое открытие. Без доступа к вебу модель может вообще её не прочитать.

Такой вариант точно выполняет требование «визуально только аэрогриль, текст внутри HTML», но работоспособность AI-механики нужно подтвердить после публикации на выбранных моделях. Локальная проверка подтверждает наличие промпта в HTML, а не его выполнение внешним ИИ.

Если нужный ИИ не видит скрытый блок, есть три технических варианта:

1. Сохранить визуальную страницу без изменений, а в копируемой фразе давать прямую ссылку на `digital-airfryer/prompt.txt`. Это уже другой адрес назначения: в браузере откроется текст.
2. Включить инструкцию прямо в копируемую фразу. Это надёжнее, но нарушает выбранное требование о короткой фразе.
3. Разместить собственный чат с сервером и API модели, который получает промпт гарантированно. Это отдельный продукт и не нужен для текущего статического лендинга.

По умолчанию ни один из этих вариантов не включён: оставлены короткая фраза и скрытый промпт, как согласовано.

## Проверка после публикации

1. Откройте вторую страницу в браузере: виден аэрогриль, промпт не отображается.
2. В исходном HTML найдите `ai-prompt`: текст должен присутствовать.
3. Скопируйте фразу на первой странице и вставьте в выбранный AI-чат с доступом к вебу.
4. Убедитесь, что сервис действительно открыл нужный URL. Не считайте любое улучшение ответа доказательством чтения скрытого промпта.
5. Протестируйте несколько запросов, включая пример про подарок из ТЗ. Сравните поведение при доступной и недоступной ссылке.

## Ссылка из интернет-магазина

После публикации разместите на demiand.ru ссылку или баннер «Сыроват ответ? Дожарь его» с адресом основного лендинга. Пример:

```html
<a href="https://USERNAME.github.io/REPOSITORY/">Дожарь ответ ИИ с DEMIAND</a>
```

Обратные ссылки из лендингов уже ведут на demiand.ru. В интернет-магазине изменения в рамках этой задачи не выполнялись.
